# Lab references: from generator functions to a JSON folder

Mirrors the earlier reference-diagram migration (`src/data/references/`), extended to course
labs. `src/data/courseLabs.ts`/`courseLabsAdvanced.ts` used to build every `LabReference` at
runtime via generator functions (`iamReference`, `networkReference`, `eksReference`,
`securityReferences`, `lambdaReference`, `pipelineReference`, `monitoringReference`) and a
`variant()` helper that cloned a base reference and mutated fields to produce related variants
(e.g. `lab5-failover` = `lab5-alb` with one task's health flipped). That trades editability for
DRY-ness: changing something shared across variants meant editing one function, not N files.

## What changed

- **`src/data/labs/*.json`** (29 files) - one JSON file per final `LabReference` (id, title,
  description, expected, optional `simulationScope`/`configurationChecks`/`authorization`, plus
  nodes/edges/scenario), named `NN-<id>.json` where `NN` is the owning lab's number.
- **`src/data/labsRegistry.ts`** - generated by `scripts/generate-labs.mjs` (mirrors
  `generate-references.mjs`): reads every file in `labs/`, validates `id`/`title`/`nodes`/`edges`
  are present and every `id` is unique, writes a flat `LAB_REFERENCES: LabReference[]` array.
- **`npm run labs:sync`** - wired into `predev`/`prebuild`/`pretest` alongside the existing
  `references:sync`, so the registry regenerates automatically.
- **`src/data/courseLabsMeta.json`** - the non-architecture metadata (which labs exist, their
  number/title/sourceUrl/objectives/limitations, and which reference ids belong to which lab) -
  this isn't split into per-lab-reference files because it isn't architecture data a student
  edits; it's hand-maintained, like `serviceCatalog.ts`.
- **`src/data/courseLabs.ts`** - now ~30 lines: reads `courseLabsMeta.json`, looks each lab's
  `referenceIds` up against `LAB_REFERENCES` (by id, preserving the metadata's own id order - the
  generated registry's order is just alphabetical-by-filename and isn't the display order), and
  throws at import time if a referenced id has no matching file, rather than silently dropping a
  lab reference.
- **`src/data/courseLabsAdvanced.ts` - deleted.** Its generator functions produced 4 of the JSON
  files' data (labs 9-13) before being retired.
- **`src/data/courseLabShared.ts`** - trimmed to just the `LabReference`/`CourseLab`/
  `LabConfigurationCheck` type definitions. The `node`/`boundary`/`edge`/`scenario`/`root` builder
  functions were dropped - nothing generates lab references at runtime anymore.

## How the migration was verified

The generator code was run once (a throwaway script, not committed) to dump its exact output -
`JSON.stringify(ref, null, 2)` per `LabReference` - directly into `src/data/labs/`, rather than
hand-transcribing 29 architecture snapshots (which risks silent data-entry errors). `npm test`
passing unchanged before and after (469/469 both times, same test count and same per-lab-reference
assertions in `test/course-labs.test.ts` - unique IDs, valid graph, deterministic simulation
outcome, subnet placement, IAM authorization, configuration-check pass/fail behavior) is the
evidence nothing was lost or altered. A new test
(`Every lab reference has its own JSON source in src/data/labs/, with no lost or extra
references`) makes that comparison a permanent regression check, mirroring
`test/reference-library.test.ts`'s equivalent check for `src/data/references/`.

## Editing workflow (deliberately asymmetric with references)

A small download icon on each reference card in the Labs modal exports that reference's current
JSON (`LabsModal.tsx`) - matching `src/data/references/`'s "Save as reference" precedent. There is
**no upload/import button** for lab references, unlike the (now also import-less, per a separate
change) reference diagram library: a lab reference can carry `configurationChecks` and
`authorization` data that need reviewing, not blind re-uploading, so editing the file and placing
it in `src/data/labs/` by hand is the only path to a permanent change. See
`src/data/labs/README.md` for the full workflow, and `docs/COURSE_LABS.md` for how to add a new
lab (not just a new reference to an existing one - that also needs an entry in
`courseLabsMeta.json`).

Full suite: 471 tests passed (442 engine/conformance + 29 UI), `tsc --noEmit` and `npm run build`
clean.
